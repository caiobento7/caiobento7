## Projetos em destaque

**[Agenda: SaaS de agendamento com Pix](https://github.com/caiobento7/agenda)**
Barbearias, estúdios e personal trainers criam a própria página de agendamento; o cliente garante o horário com um sinal via Pix. O PostgreSQL impede horário duplicado com uma constraint de exclusão, cada negócio fica isolado por Row Level Security e o webhook de pagamento é idempotente.
*Next.js, TypeScript, PostgreSQL, Drizzle, Mercado Pago, Vitest, Playwright*

**[Hub de integrações](https://github.com/caiobento7/hub-integracoes)**
Liga uma loja virtual a um ERP por uma fila no RabbitMQ. Erro temporário volta por filas de espera (5s, 30s, 2min); erro permanente vai para a fila de mensagens mortas, com reprocessamento pelo painel. Testado com RabbitMQ e PostgreSQL de verdade.
*Java 21, Spring Boot, RabbitMQ, PostgreSQL, Testcontainers, Docker*

**[Cobranças Pix](https://github.com/caiobento7/pix-cobrancas)**
API que dá baixa no Pix sem nunca contar o mesmo pagamento duas vezes, mesmo com o webhook do banco chegando repetido ou se perdendo. Conciliação agendada e devoluções idempotentes.
*Java 21, Spring Boot, PostgreSQL, Flyway, JUnit 5*

**[CursoLab](https://github.com/caiobento7/plataforma_cursos)** · [no ar](https://plataforma-cursos-omega.vercel.app)
Plataforma de cursos com compra, quizzes corrigidos no servidor, progresso por módulo e certificado em PDF.
*React, Express, Supabase, PostgreSQL*

## Como eu gosto de construir

- **O banco garante a regra**, não só um `if` no código (constraints, chaves únicas, RLS).
- **Toda operação que pode chegar duas vezes é idempotente**: webhooks, filas, pagamentos.
- **Falha temporária e falha permanente são tratadas diferente**: uma tenta de novo, a outra avisa alguém.
- **Teste que prova o problema difícil**: concorrência, fuso horário, pagamento atrasado.
- **README que explica o porquê**, não só o como.
